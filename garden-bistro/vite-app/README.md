# Replacement client — under construction

This Vite/React/TypeScript client is an **incomplete migration**, not the production website. It is not configured in the existing Netlify build. A separate `netlify.toml` can be used for an isolated staging site with this directory as its base. It includes localized public page shells, the supplied location map and a Supabase-backed list of published menu and room content. If Supabase is not configured or the query is rejected, the site displays an unavailable message; it does not fabricate listings. Staff sign-in uses Supabase Auth when configured, but no administrative authorization or dashboard exists yet. Request forms and submission are not implemented: the preview points users back to the existing site. Ordering stays closed in this client.

Run `npm ci`, copy `.env.example` to `.env.local`, supply the public Supabase URL and publishable/anon key, then `npm run dev`. Do not put a service-role key or R2 credentials in Vite environment variables. The client is deliberately noindex and is not ready for production deployment. Before cutover implement and verify server-side authorization/RLS, migration of data and media to R2, server-side business operations, full localization, remaining features and end-to-end security tests. The existing `../public` assets are used temporarily by Vite for development and build; this is not the required R2 media architecture. Published content queries require suitable, explicitly reviewed RLS policies; none are installed by this app.
